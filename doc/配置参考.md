# 配置参考

本文档说明 gotun 各类配置字段的含义与适用场景，供新建/编辑 tunnel、智能路由、内置服务时参考。

配置分三层：

| 层 | 配置 | 存放 | 说明 |
|---|---|---|---|
| 应用 | `app.yaml` | 程序启动目录 | web、日志、监控等全局配置 |
| 隧道 | tunnel | `tunnel/<name>.tun` | 一条安全通道（输入+输出+加密） |
| 智能路由 | route | `tunnel/<name>.route` | 多隧道故障转移入口 |
| 内置服务 | service | `tunnel/<name>.service` | echo/http 代理/socks5/socks5x |

---

## 1. 应用配置（app.yaml）

启动时若 `app.yaml` 不存在会自动生成并写入注释。对应 [config.go](../config.go) 的 `AppConfig`。

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `web_listen` | string | `0.0.0.0:8080` | web 管理界面监听地址 |
| `web_username` | string | `admin` | web 登录账号 |
| `web_password` | string | `admin` | web 登录密码 |
| `web_login_fail_limit_in_hour` | int | `10` | 每小时登录失败限制次数（防爆破） |
| `log_level` | string | `info` | 日志等级：`debug/info/warn/error` |
| `metrics_listen` | string | `""` | 监控监听地址（pprof 与 prometheus 共用），为空则不开启 |

> `metrics_listen` 开启后，`/metrics` 暴露 Prometheus 指标，`/debug/pprof/*` 暴露性能调试端点。详见 [Prometheus指标.md](Prometheus指标.md)。

## 2. 隧道配置（tunnel，对应 tun/config.go 的 `Config`）

一条 tunnel 表示「一种协议入口 → 一种协议出口」的转发链路，可在中间叠加加密。

### 2.1 顶层字段

| 字段 | json key | 类型 | 说明 / 场景 |
|---|---|---|---|
| UUID | `uuid` | string | 唯一标识，新建时自动生成，编辑时保持不变 |
| Name | `name` | string | 名称，全局唯一，作为配置文件名（`<name>.tun`） |
| Disabled | `disabled` | bool | 是否禁用；禁用后不监听、不转发 |
| Mode | `mode` | string | 工作模式，见下表 |
| Input | `input` | string | 入口，`proto@host:port`，如 `tcp@0.0.0.0:8888` |
| InProtoCfg | `in_proto_cfg` | string(JSON) | 入口协议扩展配置（如 tcp 的 head、socks5x 认证），结构随协议而变 |
| InDecryptMode | `in_decrypt_mode` | string | 入口侧解密方式，见「2.3 加密」 |
| InDecryptKey | `in_decrypt_key` | string | 入口侧解密 key |
| InExtend | `in_extend` | string(JSON) | 入口侧扩展（mux/探测等），结构固定为 `Extend` |
| Output | `output` | string | 出口，`proto@host:port` |
| OutProtoCfg | `out_proto_cfg` | string(JSON) | 出口协议扩展配置 |
| OutCryptMode | `out_crypt_mode` | string | 出口侧加密方式 |
| OutCryptKey | `out_crypt_key` | string | 出口侧加密 key |
| OutExtend | `out_extend` | string(JSON) | 出口侧扩展（结构同 `Extend`） |
| CreatedAt | `create_at` | time | 创建时间，自动生成 |

> 入口侧叫 **decrypt**、出口侧叫 **crypt** 是按「加密安全通道」的常规方向命名的：
> 客户端在出口加密（crypt），服务端在入口解密（decrypt）。普通明文转发两侧都留空即可。

### 2.2 工作模式 `mode`

| 值 | 说明 | 数据流 |
|---|---|---|
| `""` / `default` | 普通转发（Server）。监听 input，把每条连接经 output 转发出去 | input → output |
| `frpc` | 内网穿透客户端 | input 是「连接服务端的 worker 通道」，output 是真正要访问的本地服务 |
| `frps` | 内网穿透服务端 | input 监听业务请求，output 监听 frpc 的 worker 连接 |

> frpc/frps 模式下 input/output 的角色与 default 相反，详见 [内网穿透式安全通道.md](内网穿透式安全通道.md)。
> 一对一加密转发用 default 即可；只有「服务端无公网 IP、需反向连接」才用 frp 模式。

### 2.3 加密 `in_decrypt_mode` / `out_crypt_mode`

| 值 | 说明 |
|---|---|
| `""` / `none` | 不加密（明文） |
| `gcm` | AES-GCM 加密（目前唯一支持的非空方式） |

- 加密 key（`*_key`）会经 `StringToAesKey` 处理为 32 字节 AES key，两侧 key 必须一致。
- 构成安全通道时：客户端 `out_crypt_mode=gcm` + `out_crypt_key`，服务端 `in_decrypt_mode=gcm` + 相同 `in_decrypt_key`。

### 2.4 入口/出口协议 `input` / `output`

格式 `proto@host:port`（如 `tcp_mux@44.55.66.77:7779`）。支持的协议（[tun/enum.go](../tun/enum.go)）：

| proto | 别名 | 传输 | 多路复用 | 说明 |
|---|---|---|---|---|
| `tcp` | — | TCP | 否 | 普通 TCP，单连接单流 |
| `tcp_mux` | `tcpmux` | TCP | 是(yamux) | 一条 TCP 上多路复用，需配合 `mux_conn` |
| `udp` | — | UDP | 否 | UDP 转发 |
| `quic` | — | QUIC | 是 | 基于 QUIC，内置 TLS |
| `kcp` | — | KCP(UDP) | 否 | KCP 可靠传输，单连接单流 |
| `kcp_mux` | `kcpmux` | KCP(UDP) | 是(smux) | KCP + 多路复用 |
| `kcpx` | — | KCP(UDP) | 否 | KCP 增强版，带握手/心跳/自动重连 |
| `kcpx_mux` | — | KCP(UDP) | 是 | KCPX + 多路复用 |
| `socks5x` | — | TCP | 否 | 仅作 **input**：socks5 入口，把目标地址经通道发给对端 socks5x 服务 |

- 「多路复用」协议才能在一条底层连接上开多条流，配合 `mux_conn` 预建连接池，显著降低建连开销。
- 只有 default 模式的 **output** 支持多路复用协议（`NewOutput` 的 `makeStreamMaker`）；socks5x 只能作 input。

### 2.5 协议扩展 `*_proto_cfg`（JSON 字符串，结构随协议而变）

| 协议 | 结构 | 字段 | 说明 / 场景 |
|---|---|---|---|
| `tcp` (in) | `InProtoTCP` | `head` | 连接建立后**匹配并删除**头部字段，用于剥离伪造头 |
| `tcp` (out) | `OutProtoTCP` | `head` | 连接建立后**填充**头部数据，用于伪造流量（如伪装成 HTTP） |
| `tcp_mux` (in/out) | `In/OutProtoTCPMux` | `head` | 同上，分别用于删/填头 |
| `udp` | `UDPConfig` | `timeout` | UDP 会话空闲超时（秒），默认 90；为 0 会导致无法转发 |
| `socks5x` | `InProtoSocks5X` | 见下表 | socks5 入口配置 |
| `kcp` | `KCPConfig` | 见 2.6 | KCP 调优 |
| `kcpx` | `KCPXConfig` | 见 2.6 | KCPX 调优（含 KCP 全部字段+握手心跳） |
| `quic` | `QUICConfig` | （空） | 暂无扩展字段 |

**socks5x `InProtoSocks5X`：**

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `username` / `password` | string | `""` | socks5 认证账号密码，为空表示不校验 |
| `tcp_timeout` | int32 | `300` | socks5 TCP 连接空闲超时（秒） |
| `udp_advertised_ip` / `udp_advertised_port` | string / int | `""` / `0` | UDP ASSOCIATE 时告知客户端的 UDP 入口地址。需另建一条 udp 安全通道后，把该通道客户端的 ip/端口填在这里，见 [内置socks5安全通道.md](内置socks5安全通道.md) 的 udp 部分 |

### 2.6 KCP / KCPX 调优 `KCPConfig` / `KCPXConfig`

KCP 字段（`kcp`/`kcp_mux` 使用，默认见 `defaultKCPConfig`）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `mtu` | 990 | 最大传输单元 |
| `sndwnd` / `rcvwnd` | 2048 / 1024 | 发送/接收窗口（包数） |
| `datashard` / `parityshard` | 0 / 0 | Reed-Solomon 前向纠错分片，>0 开启 FEC 抗丢包 |
| `dscp` | 46 | IP 层 DSCP QoS 标记 |
| `nodelay` / `interval` / `resend` / `nc` | 0/30/0/0 | KCP 快速模式参数（是否 nodelay、内部更新间隔 ms、快速重传阈值、是否关拥塞控制） |
| `acknodelay` | true | 收到包立即回 ACK |
| `write_delay` | true | 写延迟合并小包 |
| `sockbuf` | 16777217 | UDP socket 读写缓冲区（字节） |
| `streambuf` | 4194304 | smux 流接收缓冲（字节，mux 模式用） |

KCPX 在以上字段之外增加（`kcpx`/`kcpx_mux`，默认取自 `kcpx.DefaultOptions()`）：

| 字段 | 说明 |
|---|---|
| `handshake_timeout_ms` / `handshake_retry_interval_ms` / `handshake_max_retries` | 握手超时/重试间隔/最大重试 |
| `heartbeat_interval_ms` / `heartbeat_timeout_ms` | 心跳间隔/超时，用于保活与判死 |
| `reconnect_retry_interval_ms` / `reconnect_max_retries` / `enable_auto_reconnect` | 断线自动重连相关 |

> KCPX 适合对稳定性要求高的弱网场景，普通场景用 kcp/tcp 即可。

### 2.7 扩展 `in_extend` / `out_extend`（JSON，结构固定为 `Extend`）

| 字段 | json key | 类型 | 默认 | 说明 / 场景 |
|---|---|---|---|---|
| MuxConn | `mux_conn` | int | 0 | 多路复用**预连接数**。仅 `tcp_mux/quic/kcp_mux/kcpx_mux` 等 stream 协议有效；>0 表示预建 N 条底层连接做连接池。非 stream 协议必须 ≤0，stream 协议必须 >0（否则 `CheckCfg` 报错） |
| AutoExpire | `auto_expire` | int | 0 | 连接池里底层连接的存活秒数，>0 时到点自动重建连接（应对运营商/NAT 老化） |
| FrameHeaderEnable | `frame_header_enable` | bool | false | 是否启用「帧头」协议。开启后才支持**链路质量探测**与**带宽测试**（帧头携带 stream 角色握手 + probe/bandwidth 帧）。需通道两端同时开启 |
| ProbeIntervalSec | `probe_interval_sec` | int | 2 | 链路探测节奏（秒一次） |
| ProbeTimeoutMS | `probe_timeout_ms` | int | 1500 | 单次探测超时（毫秒） |
| ProbeWindowSize | `probe_window_size` | int | 5 | 探测滑动窗口样本数，据此算 RTT/丢包/抖动与健康状态 |

> **帧头（frame_header）** 是 gotun 自定义的轻量协议：在加密流上加 6 字节握手（magic+version+role）
> 标记该流是业务/探测/带宽流，再以「类型+长度+载荷」帧传输。开启 `frame_header_enable` 后
> web 上的健康徽标、RTT/丢包指标、带宽测试才可用。健康数据见 [Prometheus指标.md](Prometheus指标.md)。

## 3. 智能路由配置（route，对应 `RouteConfig`）

智能路由把多条已存在的 tunnel 作为「成员(member)」，按优先级 + 健康状态做**故障转移**：流量自动走当前优先级最高且可用的 member。

| 字段 | json key | 类型 | 说明 / 场景 |
|---|---|---|---|
| UUID | `uuid` | string | 唯一标识，自动生成 |
| Name | `name` | string | 名称，不能与已有 route 或 tunnel 重名 |
| Disabled | `disabled` | bool | 禁用后不监听（但仍跟踪 member 健康变化） |
| Mode | `mode` | string | `output`（出口）/ `input`（入口），默认 `output` |
| Listen | `listen` | string | 监听地址。output 模式带协议 `proto@host:port`；input 模式为裸 `host:port` |
| InProtoCfg | `in_proto_cfg` | string(JSON) | 仅 output 模式：入口监听协议的扩展（如 socks5x 认证）。input 模式是裸 TCP 透明转发，无此配置 |
| Members | `members` | []string | member tunnel 名称列表，**数组顺序即优先级**，索引 0 最高 |
| Policy | `policy` | string | 故障转移策略，v1 仅支持 `priority` |
| CreatedAt | `create_at` | time | 创建时间 |

**两种模式的区别：**

- **output 模式**：本地起一个带协议的入口（如 socks5x），把流量经「选中的 member 的 output（含其加密/帧头）」发出去。客户端只需对路由入口讲协议，转发与加密由 member 承担。
- **input 模式**：裸 TCP 透明转发，把字节原样转发到「选中的 member 的 input 监听地址」。要求所有 member 的 input 协议一致。

选址规则（`routeSelector.memberAlive`）：member 须存在、未禁用、状态为 `running`、健康非 `down`。
未开帧头探测（健康为 unknown/disabled）的 member 仍可被选中。

## 4. 内置服务配置（service，对应 server/service/config.go 的 `Config`）

内置服务是便于测试/部署的本地服务，在 web「内置服务」菜单管理，配置存 `tunnel/<name>.service`。

| 字段 | json key | 适用类型 | 说明 |
|---|---|---|---|
| Name | `name` | 全部 | 实例名 |
| Type | `type` | 全部 | `echo` / `http_proxy` / `socks5_server` / `socks5x_server` |
| Disabled | `disabled` | 全部 | 是否禁用（停用释放端口，启用恢复） |
| Listen | `listen` | echo / http_proxy | 监听地址，如 `0.0.0.0:8081` |
| ListenPort | `listen_port` | socks5 / socks5x | 监听端口 |
| TCPTimeout | `tcp_timeout` | socks5 / socks5x | TCP 空闲超时（秒） |
| UDPTimeout | `udp_timeout` | socks5 / socks5x | UDP 空闲超时（秒） |
| Username / Password | `username`/`password` | socks5 | 可选认证账号密码 |

各类型用途：

- **echo**：收发原样回显，常用于验证链路是否打通（配合 `nc` 或 web 测试工具）。
- **http_proxy**：HTTP/HTTPS 代理。
- **socks5_server**：标准 socks5 代理。
- **socks5x_server**：自定义 socks5x 协议服务端，作为「内置 socks5 安全通道」的对端，见 [内置socks5安全通道.md](内置socks5安全通道.md)。

## 5. 配置存储与热更新

- tunnel/route/service 每类一个文件，存于 `tunnel/` 目录，后缀分别为 `.tun`/`.route`/`.service`。
- 写入均为**原子写**：先写 `.staging/` 临时文件再 `rename`；替换时先备份 `.bak`，失败回滚。
- web 上的增删改即时生效，无需重启；启动时按 `.tun` → `.route` 顺序加载（保证 route 的 member 已注册）。
