# 智能路由入口的完整链路探测与选路

本文仅保留可公开的通用配置与规则；包含现场地址和部署记录的验证文档保存在本地，不纳入版本控制。

「智能路由 · 入口」的「优先级故障转移（完整链路）」和「质量优先（完整链路）」共用相同的探测器、配置与指标，仅选路规则不同。新建入口默认选择质量策略。完整链路探测只支持明文且未启用 input 帧头的 `socks5x` 成员，支持其账号密码；其他组合会在保存时明确报错。智能路由出口模式仍沿用单跳健康选路。

探测经过每个成员自己的 SOCKS5 监听口、完整多跳隧道、出口代理及 HTTPS 目标。帧探测在第一跳就响应，因此列表中的单跳健康不能代替完整链路结果。线路按时间预算评估，不按 RTT 排名。

## 默认配置

| 参数 | 默认值 |
| --- | --- |
| 下载目标 | `https://speed.cloudflare.com/__down?bytes=16384` |
| 连通性目标 | `https://www.gstatic.com/generate_204` |
| 下载预期状态码 / 字节数 | 200 / 16384（16 KiB） |
| 连通性预期状态码 | 204 |
| 间隔 | 30 秒 |
| 单个请求总超时 | 5000 毫秒 |
| 正常完成时间 | 2000 毫秒 |

所有参数均可在前端修改，并保存进 `.route` 文件的 `quality` 对象。两个目标必须是 HTTPS，预期状态码限 2xx；下载字节数为 1–1048576，间隔为 10–3600 秒，总超时为 100–30000 毫秒。正常时间必须大于零且不超过总超时。更换下载大小后，需同时调整 URL 参数或自建文件大小，程序校验精确响应长度。

下载失败后才发起连通性确认，两者各自使用总超时，最坏一轮可能耗时两倍总超时；同一路由不会重叠执行探测轮次。每个请求使用新的 SOCKS/TLS 连接，保持证书校验，禁止自动跳转和压缩；下载最多读取预期长度加一个字节。连通性确认只校验状态码，其成功不会抵消下载失败。

## 共用指标

- 正常：按正常时间完成且状态码、正文长度正确。
- 慢：超过正常时间，但在总超时内完整完成。
- 失败：超时、断连、状态码或正文长度错误等。
- 不良次数：最近 20 个有效轮次中的慢与失败次数。
- 连续正常次数：连续按正常时间完整完成的轮数；慢或失败均重置。

## 优先级故障转移

启动时按配置顺序选择运行中的成员，并立即开始探测。当前连续失败 3 次，且备用连续正常 2 次时，按配置顺序选择第一个满足条件的备用；故障转移不受冷却限制，不必等待 20 次窗口收满。

高优先级成员恢复为连续正常 2 次，且距上次切换已满 60 秒时，自动回切到符合条件的最高优先级成员。慢请求仍进入不良统计，但不单独触发优先级策略切换；即使备用不良次数更少，也不会因此切换。

当前成员被禁用、删除或停止运行时立即跳过，优先选择连续正常 2 次的备用；没有可靠备用则按顺序尝试运行中的成员。没有任何运行成员时，首选为空。

## 质量优先

当前连续失败 3 次，且备用连续正常 2 次时故障切换。双方窗口满 20 次后，备用不良次数至少少 3 次且最近请求成功时，允许质量切换。质量切换冷却 60 秒，故障切换可绕过冷却。候选质量相同时按配置顺序选择，但质量相同不会使已恢复的原首选抢回。窗口未满时显示评估中，按 30 秒周期约需 10 分钟收集完整窗口，故障切换不必等待窗口满。

## 共用异常处理与记录

同一轮至少两条运行线路下载全部失败时，显示共同失败，整轮不进入质量窗口。若辅助连通性成功，清除该线路的连续故障计数；若辅助也失败，保留连续失败以便另一条线路恢复后避让。所有线路都异常且没有更好候选时保留当前选择，不凭空切换到另一条未知线路。成员被禁用、删除或停止运行时立即跳过；成员重建后清空其旧窗口。

切换只影响新连接，已有 TCP 连接不会迁移。编辑、禁用、删除路由会取消旧探测；重启后重新收集窗口。两种策略均通过 `member_quality` 返回完整链路数据，包括 `consecutive_normal` 连续正常次数；原单跳健康兼容字段继续保留。路由列表以完整链路结果为准，优先级策略突出连续失败和连续正常，不因窗口未满一直提示评估中；「切换记录」显示故障转移、恢复回切或质量切换的具体原因。逐次结果在「隧道管理」对应成员的「… → 探测历史」中查询，包含来源入口，持久化保留最近 7 天；重启不会清除这些历史，详见[逐次探测历史](probe-history.md)。

## 流量与边界

前端按 `下载字节数 × 30 × 86400 ÷ 间隔秒数 × 成员数` 估算每月正文流量。默认每条约 1.42 GB/月，两条约 2.83 GB/月，不含 TLS、协议、辅助请求和重传开销。同一成员被多个入口引用时，每个入口分别探测并产生流量。两种完整链路策略均产生相同探测流量；禁用入口、出口模式和旧版单跳兼容入口不产生本功能的探测流量。

小文件探测衡量短请求的稳定性和停顿，不等同于 TCP 丢包率，也不能保证持续大文件下载能力。公共目标可能发生共同异常；长期可换为独立于隧道节点的自建 HTTPS 文件。探测目标应代表实际访问方向，不能只使用香港或新加坡的回环服务。

## 构建和启用

页面通过 embed 打包，需要编译并部署 Go 二进制后才能使用新界面：

```powershell
go build -o bin/gotun-quality.exe ./cmd
```

部署后，兼容的旧优先级入口会在加载时补齐默认参数，自动使用完整链路探测；内存中升级不会立即改写原文件，保存或启停时才持久化。两种策略切换会保留 `quality` 配置。

不兼容的旧优先级入口继续按原单跳规则运行，API 和界面明确显示 `probe_mode=legacy_frame` 及 `probe_warnings`，列出不兼容成员和原因；启停仍可正常使用。编辑保存时必须先将成员调整为支持完整链路探测的配置，保存后升级为 `probe_mode=full_path`。新建入口不能指定旧版模式；已显式保存为 `full_path` 的入口重启加载时不会静默降级。旧版兼容入口重启时若成员已支持完整链路探测，也会自动升级。质量策略和出口模式没有旧版入口回退逻辑。
