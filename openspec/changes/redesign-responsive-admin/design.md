## 背景

沿用现有 Go embed、Vue 2、http-vue-loader 与 iView 运行时；前端仅有编译后的启动包及动态 SFC。布局依据为已获用户确认的 `docs/ui-preview/app.html`；文字颜色和字号以随后确认的 `docs/ui-preview/contrast-v2/` 方案 02 为准。

## 目标与边界

实现四个管理列表、导航和隧道表单的统一响应式界面。后端协议、持久化及探测生命周期保持兼容，不增加前端打包链。

## 决策

- 在静态资源目录增加共享 CSS 和界面辅助脚本，通过入口页面加载；动态页面继续沿用现有接口方法。相比引入新框架，避免改动路由和终端生命周期。
- 共用列表 mixin 处理当前页搜索、状态筛选、加载失败与统计。搜索范围明确标注为当前页，保留后端分页语义。
- 使用相同数据驱动桌面表格与手机卡片；900px 切换导航和卡片，760px 以下卡片单列。表单采用原生网格与现有输入组件，高级协议参数折叠。
- 弹窗使用既有 iView 组件，统一手机底部面板、最大高度及内容滚动；MTR 保留独立终端样式。
- 实际运行状态与健康状态分别展示；启停请求成功后刷新，失败显示错误，保存失败不关闭表单。
- 主要文字采用 `#1f2937`，地址采用 `#263443`，辅助文字使用 `#475569` / `#526171`；正文不再使用浅绿色。表头加粗，桌面地址 14px、手机地址 13px；绿色用于按钮、开关和状态。调整共享主题和必要的局部说明，同时更新资源版本避免浏览器复用旧样式。

## 风险与权衡

- 动态模板不能由 Go 编译发现语法问题 → 浏览器运行真实入口并覆盖四个页面、表单及错误路径。
- 前端资源和二进制不一致 → 构建 Go 二进制并验证 embed 后的资源可访问。
- 窄屏长地址与终端溢出 → 使用长名称、IPv6 及手机宽度检查整页溢出，终端局部滚动。

## 交付与回退

运行 OpenSpec 校验、现有 Go 测试及浏览器验证后重新构建。部署时替换二进制并刷新缓存；回退可直接恢复此前二进制，无配置迁移。
